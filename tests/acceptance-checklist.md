# Behavioral Acceptance Checklist

For each scenario, verify the observable output rather than inferred intent.

- [ ] Selects the expected current stage.
- [ ] Does not restart an irrelevant upstream stage.
- [ ] Labels verified facts, inferences, hypotheses, and unknowns distinctly when claims are evaluated.
- [ ] Does not invent data, methods, citations, experimental details, statistics, or mechanisms.
- [ ] Asks no more than one genuinely blocking question.
- [ ] Produces the required current-stage artifact.
- [ ] Ends a substantive response with all eight decision-card fields.
- [ ] Preserves scientific meaning during English revision.
- [ ] Does not strengthen certainty, causality, novelty, or scope without evidence.
- [ ] Reports integrated audit findings in P0, P1, P2, P3 order.
- [ ] States what is checked and unchecked before making a readiness judgment.
- [ ] Defines the next-stage admission condition or explains why the current stage remains blocked.

## Release rule

Do not mark behavioral validation as passed unless every scenario is executed in a fresh context and every applicable assertion above is inspected. Structural validation alone must be reported separately.
